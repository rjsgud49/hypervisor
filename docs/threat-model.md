# 위협 모델 (초안)

기능 PoC와 함께 **H1(네이티브 외관)·H3(상호 미감지)** 위반을 위협으로 취급한다.  
제약은 [`isolation.md`](isolation.md).

---

## 자산

| 자산 | 설명 |
|------|------|
| 네이티브로 보일 권리 (H1) | 앱이 VM/가상 서비스로 분류하지 않음 |
| 프로세스 상호 비공개 (H3) | 상대 OS 프로세스·세션 불가시 |
| 메인 OS UX·데이터 | 사용자 세션, 파일, 계정 |
| 화면 내용 | 프레임에 비밀 포함 가능 |
| HV 통신 채널 (H2) | 화면·제어 — 존재 자체가 탐지 표면이 될 수 있음 |
| 외부 하드웨어 | 물리 부작용 |
| 하이퍼바이저 | 전 시스템 TCB |

---

## 신뢰 경계

```
[External HW] ←── Sub OS (독립 프로세스 공간)
                     ↕ HV-only channel (게스트 앱에 상대 OS 미노출)
                 Main OS (독립 프로세스 공간)
                     ↑
              Hypervisor / IOMMU  (유일한 크로스-OS 특권)
```

- 메인 앱 ↔ 서브 앱: **상호 비신뢰·상호 불가시**
- 게스트 유저/커널은 상대 게스트 메모리를 볼 수 없음
- 하이퍼바이저만 양쪽 중재 (이 권한이 게스트 프로세스로 내려오면 H3 붕괴)

---

## 위협 (STRIDE + 탐지)

| ID | 위협 | 예시 | 완화 방향 |
|----|------|------|-----------|
| T1 | 서브 탈취 | 악성 연산 | 서브 최소화, 채널 allowlist |
| T2 | 화면 도청 | 링버퍼 스니핑 | EP 권한·ROI·감사 |
| T3 | 악의적 제어 | 임의 입력 | opcode allowlist, rate limit |
| T4 | HW 오남용 | 위험 신호 | fail-safe, 인터록 |
| T5 | DoS | 프레임 홍수 | FPS/대역 상한 |
| T6 | HV 탈출 | 게스트→HV | 패치, 장치 최소화, IOMMU |
| T7 | **가상화 탐지 (H1)** | 장치/CPUID/서비스/프로세스 지문 | 패스스루, 지문 제거, 게스트 툴 금지 |
| T8 | **크로스-OS 프로세스 감지 (H3)** | 게스트 툴 API, 호스트 디버그, 공유 FS | Type-1, 툴 제거, 프로토콜에 PID 금지 |
| T9 | 채널 존재 탐지 | 이상 PCI·숨은 디바이스 노드 | EP를 정상 로컬 장치처럼·최소 노출 |

---

## 보안·격리 요구

1. 제어 API: 입력/윈도우 **allowlist만**, 프로세스 열거 opcode 없음
2. 화면 메타데이터에 PID·프로세스명 금지
3. 게스트 툴·공유 폴더·클립보드 공유 기본 OFF
4. Type-2 호스트 디버그 경로를 최종 구성에 포함하지 않음
5. 감사 로그는 **로컬 frame_id / req_id** 중심 (상대 PID 없음)
6. 서브 아웃바운드 네트워크 기본 차단 (별도 정책)
